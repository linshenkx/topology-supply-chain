# 结果状态、缺陷严重度与继续/阻断规则

## 结果状态

| 状态 | 含义 | 必备内容 |
| --- | --- | --- |
| PASS | 达到预期，且证据齐全 | 预期 + 证据路径 + 清理状态 |
| PASS_WITH_ISSUES | 主预期达到，存在非阻塞问题 | 问题 ID + 证据路径 |
| FAIL | 未达预期 | 首个失败响应/截图/日志，不得覆盖原失败 |
| BLOCKED | 测试环境、fixture、角色、载体或授权缺失，无法执行 | blockedReason + 交接对象；不得写成产品 FAIL |
| HUMAN_CHECKPOINT | 需要真人在场观察或输入 | 交接对象 + 保留现场证据 |
| NOT_RUN | 本批次未执行（计划内跳过） | 跳过原因 |
| NOT_APPLICABLE | 超范围或无适用 fixture | 依据 coverage-matrix |
| NEEDS_DECISION | 业务语义不明确 | 决策问题，不当作代码缺陷 |

机器值沿用上述大写；manifest 必须使用枚举值，禁止 skip 冒充 PASS。

## 缺陷严重度

| 严重度 | 定义 | 处置 |
| --- | --- | --- |
| Blocker | 主链无法完成、安全绕过、数据损坏/错账、敏感信息泄露 | 停止该链/该 RUN，保存证据并通知验收负责人 |
| Major | 主要功能错误，但不影响其他模块继续 | 该用例 FAIL 或 PASS_WITH_ISSUES，登记问题，可继续其他用例 |
| Minor | 交互、提示、展示、文案问题 | 只记录，不修 |
| Observation | 改进建议、非功能观察 | 只记录，不修 |
| NeedsDecision | 业务含义/预期未定义 | 升级 needs_decision，不做缺陷定级 |

## 继续/阻断规则

1. Tier 0 失败：停止，不进入 Tier 1。
2. status 任一 ready 检查失败或 repositorySha 不一致：BLOCKED，停止写场景；该结论只描述测试无法执行，不描述产品功能失败。
3. Blocker：停止受影响业务链/该 RUN_ID；不依赖它的其他测试可以继续。
4. Major：记录问题，可继续同一模块其他用例，但该模块结论不得为 PASS。
5. Minor / Observation / NeedsDecision：记录并继续。
6. HUMAN_CHECKPOINT：暂停该用例，不阻塞不依赖它的独立用例。
7. 非阻塞问题只记录不修；任何修复都应另行评估和授权，验收执行者不得顺手修改生产或测试代码。

## 结论复核

- 每个场景只保留一个最终结果；自动化、Agent 或真人产生的证据由验收负责人统一复核，禁止互相覆盖首个失败。
- 同一失败原因最多进行一次有界重试。已有可用执行方式时应复用，不为测试载体重复设计或排障。
- 自动化已经覆盖的负路径可以直接引用现有证据；浏览器验收不要求重复全部合同测试。
